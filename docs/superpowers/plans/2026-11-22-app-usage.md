# App Usage Tracking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record the foreground window's app + title on Windows desktop clients and show System Admins per-user daily app time next to the Breaks report; hide the break counter from the status box.

**Architecture:** The desktop main process samples the foreground window every 5 s (koffi → user32/kernel32), merges samples into ≤ 60 s intervals, and keeps a queue per server. The webapp pulls its server's queue every 60 s through `desktopAPI.getAppUsage()` and posts it to `POST /api/v4/app_usage`. The server stores raw intervals in `AppUsage` and returns per-(user, app, title) sums for a range to admins.

**Tech Stack:** Go (server, squirrel/sqlx, Postgres migrations), React + TypeScript (webapp), Electron + koffi (desktop).

**Spec:** `docs/superpowers/specs/2026-11-22-app-usage-design.md`

## Review Focus

1. **Sleep / lock with no idle reported:** if the machine sleeps, timers stop; on wake the open interval must not stretch across the gap. Expected: a tick arriving more than 15 s after the previous one closes the open interval at the previous tick. (Test in Task 6.)
2. **Retried batch:** the webapp re-posts a batch after a timeout that actually succeeded. Expected: no duplicate rows (unique `(UserId, StartAt)` + `ON CONFLICT DO NOTHING`). (Tests in Tasks 1 and 2.)
3. **Spoofed user:** a client posts rows with someone else's `user_id`. Expected: stored under the session user. (Test in Task 2.)
4. **Titles with emoji / non-Latin text over the limit:** truncation by runes, never splitting a character. (Test in Task 1.)
5. **Interval crossing midnight:** the report for a day only counts the part inside that day. (Store test in Task 1.)
